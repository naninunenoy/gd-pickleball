# ピックルボールらしさ：試合の読み方とゲーム設計の仮説

このメモは、素人〜中級者手前の試合理解から、テニスゲームを模倣しない設計仮説までをまとめたもの。現行スライス（俯瞰2Dダブルス）の実装仕様は [`rules.md`](rules.md) / [`implementation.md`](implementation.md) を正とする。ここは次の体験を考えるための議論メモ。

---

## 1. 試合における駆け引き（素人〜中級者手前）

派手な決め球の応酬より、**ミスを誘う位置取りとテンポの押し引き**が中身。軸はどれも同じで、**ネット前（キッチンライン）を取った側が有利**。日本のレクリエーションはほぼダブルス前提。

### 素人（ルールを覚えた直後〜数回）

戦術というより、誰が先にミスするか。

- 強打したい衝動 vs コートに入れる我慢
- ネット前に出るか、後ろで待つか
- 真ん中のボールの取り合い（声がないとお見合い／ダブルヒット）
- キッチンに足が入ったボレーでフォルト

効くこと：サーブとリターンを深く入れる、リターンしたらすぐ前に詰める、相手の真ん中または足元、自分が決めにいかず相手のミスを待つ。

### 初心者（ルールは分かり、ラリーが少し続く）

ポイントの型が見え始める。

1. サーブ
2. リターン（深く）→ レシーブ側がネット前へ
3. サーブ側の3球目
4. 両ペアがネット前に揃うか、片方が途中で詰まる
5. 短い応酬のあと、浮き球を叩くかミスで終わる

この段階の駆け引き：

1. **位置** — サーブ側は後ろ、リターン側は前。ワンアップ・ワンバックは真ん中と斜め前が空く
2. **3球目** — 深い低いリターンにはドロップ、浅く高いリターンにはドライブ
3. **ディンクの入り口** — クロスが基本、足元・バックハンド、浮いた球だけ叩く。「先に叩いた方が勝ち」ではなく「先に浮かせた方が負け」
4. **狙う場所** — 相手ペアの真ん中、バックハンド側、前に出きれていない人
5. **ペアの会話** — 真ん中はフォア、ドロップで前に出る、リセット

### 道具を揃えた中級者手前（おおよそ 2.5〜3.0）

技術より選択が試合を決め始める。スタッキングやエルネはまだ不要。

- **ソフト vs ハード** — バンガーには低い球とディンクでスピードを殺す。ソフトばかりなら浅い／高い球だけ揺さぶる
- **3球目の二段構え** — 1球で決めず、次の自分が前に出られる球を打つ。甘いドロップならリセット
- **ディンクでの揺さぶり** — クロス基本、たまに真ん中、左右の足元、深め／短め。スピードアップは浮き気味の球に限定
- **トランジションの生存** — 中間位置は一番危険。低い球はリセット、高い球だけ叩く、横並びを崩さない
- **サーブ／リターンの意図** — 次の立ち位置を買う球。短いサーブは相手に楽に前へ出られる
- **相手観察** — 弱い側、ネット前か後ろの強打か、真ん中を誰が取りたがるか、ディンクで焦るか

今すぐ使える判断基準：

1. リターンしたら必ず前へ。サーブ側は3球目のあと2人で前へ
2. 低い球は柔らかく、高い球だけ叩く
3. 狙いはセンターとバックハンド
4. ペアは横一列。片方が出たらもう片方も出る
5. 先に決めにいった側が負けることが多い。浮くまで待つ

レベル別で何を読み合っているか：

| 段階 | 試合で実際に起きている駆け引き | まだ早いもの |
|------|----------------------------------|--------------|
| 素人 | 入れるか、前に出るか、真ん中を誰が取るか | 球種の使い分け |
| 初心者 | キッチンを取る競争、3球目、真ん中／バック狙い | スピードアップの応酬 |
| 中級者手前 | ソフトとハードの切り替え、ディンクで浮き球を作る、リセット、弱点固定 | スタッキング、エルネ |

## 2. 成功体験とは何か

試合に勝つことそのものではない。**「正しい選択をした結果、次の一球が楽になった」と自分で分かった瞬間**。

重なる3つ：

1. 自分の判断が、コート上の状況を変えた
2. それを再現できる感覚が残った（たまたま入った一球ではない）
3. 残すべき打ち方が強化された（強打の快感より、低く返して相手が浮かせた快感）

勝敗は結果。成功体験は **なぜ点が入ったか／入らなかったかを、自分の選択と結びつけられたこと**。

### レベル別

- **素人** — 点が取れる形を一つ知ること。入れる、前に出る、真ん中を被らず取る、強く打たずに返したら相手がネットした。偽の成功はフルスイングが1本決まること
- **初心者** — ポイントの型が残ること。深くリターンして先に立つ、3球目を落として並んで出る、浮くまで待つ。不利な位置からネット前に戻れた方が大きな成功
- **中級者手前** — 相手を動かして悪い選択をさせたこと。使い分け、揺さぶり、リセット、弱点への固定。自分が決めた瞬間より、相手が崩れた瞬間を意図と結びつけられたこと

成功に見えるが上達を止めるもの：ベースライン強打の一発、運のロブ、早打ちが当たる、ペアが全部決める、道具を変えた直後の好調。

意図的に作るなら、試合前に約束を1つだけ置く（リターンのあと必ず前に出る、低い球を叩かない、など）。守れれば負けていても成功。練習では成功の定義をさらに小さくする（ディンク10本、ドロップは「相手が強打できない高さ」）。

## 3. 「キッチンを取る」とは

前に走ることは条件の一部で、それだけでは取れていない。**取れた**と言えるのは、2人がネット前で構えた状態のまま、次の球を処理できるとき。走っている途中に球が来るなら、一番危険な場所（トランジション）に自分から入っている。

キッチン（非ボレーゾーン）はネットから約7フィート。目的は中に飛び込むことではなく、**線の外側（キッチンライン）に2人で立ち、そこを維持すること**。

取れている状態：

- 2人が横並びでラインに着いている
- 止まって構えている（走り終わっている）
- パドルが前に出ている
- 次の球が来ても、ボレーかディンクで返せる
- 相手より先に、または対等に、その場所を占めている

走ってよいのは、相手が強打しにくい球を自分が先に出してから、その球が飛んでいるあいだ。

- **リターン側** — 2バウンド・ルールにより、深く返したあと相手の3球目まで時間がある。ここで走るのは正しい
- **サーブ側** — サーブ直後に走ると深いリターンが足元に来る。先に3球目（ドロップ、または浅いリターンへのドライブ）を出してから2人で出る

判断：相手が強打しにくい球を打った → 走る。相手が打ちやすい高さ・浅さになった → 走らない。リセットしてから出直す。

| ただ前にいる | キッチンを取っている |
|--------------|----------------------|
| 着いたがパドルが下がっている | 次の球に間に合う位置で構えている |
| 片方が前、片方が後ろ | 2人が横一列 |
| 低い球を強打して自滅する | 低い球はディンク／リセット、高い球だけ叩く |
| 押されてすぐ下がる | 下がらず、柔らかく返してその場を守る |
| キッチンに踏み込みながらボレーする | 線の外で打ち、中にはバウンド後だけ入る |

短い定義：

- 前に走る = 移動
- キッチンを取る = **相手が罰しにくい球のあと、2人でラインに着き、そこで次の点を支配できる状態を作ること**

## 4. 点のフェーズ

ダブルスの点は、原則この順で進む。

1. **キッチンを取りにいく** — リターン側が深く返して先に着く。サーブ側は3球目で追いつく
2. **片方だけが取れている** — 前にいる側は相手が着く前に優位を使う。後ろの側はしのいで追いつく
3. **両方とも取れている** — ディンク、リセット、浮いた球のスピードアップ

この3つは別ゲームで、やるべきことが違う。

### 「決めたい」の中身（1点だけ修正）

「キッチンを取った方は、相手が来る前に決めたい」は、有利を使いたいという意味では正しい。ただしフルスイングして決める、ではない。

前にいる側の仕事：

- 相手の足元、特に走っている途中の足元に置く
- 高い球だけ叩く
- 相手を中途半端な位置に留めて、着かせない

「決め切る」より **着かせない** が本体。早く決めにいってネット／アウト／カウンターされるのが、このフェーズ一番多い自滅。

### 何割の点で起きるか

考え方としてはほぼ100%使ってよい地図。実際に3段すべてを通る点は、素人〜中級者手前だと半分以下が多い。

| 実際に起きること | 目安（素人〜中級者手前） |
|------------------|--------------------------|
| サーブ・リターン・3〜4球目で終わる | 4〜6割 |
| 片方だけキッチン、もう片方は途中 | 2〜4割 |
| 両方キッチンまでいってディンクになる | 1〜3割 |

- 地図としては9割以上の点に使える
- 3段全部を通る点は、今のレベルだと2〜3割
- 「8割」が近いのは、点のほとんどが両方キッチンのディンク戦で決まる、という意味ではなく、**点のほとんどが『キッチンを取る／取られる』の前後で決まる** という意味

3.0前後では、決め球の約7割は先に2人ともキッチンに着いた側が出す。ベースラインからの決め球はほぼゼロ。ミスの多くはキッチンへ移動中と、着いてからのボレー。

例外（残り1〜2割）：サーブ／リターンの即失点、両方後ろのまま打ち合う、ワンアップ・ワンバックのまま崩れる、ロブでフェーズ2に戻る。

試合中に聞くこと：

- 今は取りにいっているか
- 片方だけ取れているか
- 両方取れているか

**型としてはほぼ100%。最後まで通る点は8割ではない。今のレベルなら、点の8割は途中のフェーズで終わっている。**

## 5. ゲームを読む肝はフェーズか

はい。ピックルボールの試合を読む主軸は、テニスの「サーブから展開」や「フォアのサイドを攻める」より、**今どのフェーズにいるか**。

コートが小さく、ネット前に立てるかどうかで有利不利がほぼ決まる。点の意味は球種の名前より先に、**位置関係**で読んだ方が正確。

読む順番：

1. 今どのフェーズか
2. どちらが止まって構え、どちらが移動中か（止まっている側が強い）
3. 次の球の高さ（低い球はしのぎ、高い球だけ叩く）
4. ペアが横並びか

肝なのはフェーズ名を覚えることではなく、フェーズが変わると **やるべき駆け引きが切り替わる** こと。

- 取るまで: 深さ、3球目、2人で着く
- 片方だけ: 着かせない／しのいで着く
- 両方: 浮くまで待ち、先に飛ばした側が負ける

試合中は戦術をたくさん持たなくてよい。**今どこにいるかを見て、そのフェーズの仕事だけする。**

## 6. メジャーなテニスゲームの面白さの軸

実テニスの「フェーズを読み切る」より、**一打の打感と、その積み重ねで相手を崩すこと**に置かれている。

共通ループ：

1. ボールの落下点へ動く
2. タイミングと位置で一打の質が決まる
3. 良い球は相手を走らせ、悪い球は自分を走らせる
4. チャンス球でコースを切って決める

本体は戦術マップではなく、**「今の一打がどれだけ気持ちよいか／まずいか」が即座に分かること**。実テニスでは点がミスで終わりやすいが、ゲームはラリーを続きやすくし、勝者側に「自分が決めた」感覚を渡す。ビデオゲームのテニスは、スポーツ中継より対戦格闘に近い。

| 軸 | 代表 | 何が気持ちいいか |
|----|------|------------------|
| タイミングと位置 | バーチャテニス | 完璧な一打、ウィナー |
| ショット作成と組み立て | トップスピン | 実テニスらしい構築 |
| ゲージと読み合い | マリオテニス | 必殺、逆転、キャラ差 |
| 身体動作 | Wiiスポーツ | 振ること自体 |

テニスゲームが意図的に薄めるもの：サーブ・リターンのミス量産、高い球だけ叩く忍耐、ダブルスの「横並びでキッチンを取る」ような位置フェーズ。

対比：ピックルボールの肝がフェーズの切り替えなら、メジャーなテニスゲームの肝は、そのフェーズを省略してでも打ち合う快感を残すこと。

## 7. ピックルボールゲームの設計仮説（テニスを模倣しない）

最初に置く仮説は「テニスの打感を小さいコートに移植する」ではなく、**点がフェーズで切り替わり、その切り替え自体が上手さとして感じられるか**。固有の体験は強い一打ではなく、位置・高さ・2人の並びが変わった瞬間。

### 最初に試す仮説

1. **面白さの核は「今どのフェーズか分かること」**  
   取りにいっている／片方だけ／両方。フェーズが見えないゲームは、球種を増やしてもピックルボールにならない。フェーズが変わった瞬間に操作の正解が変わることを、チュートリアルなしで感じられるかを見る。

2. **読むべき情報は速さより高さ**  
   「叩いてよいか」はコースや速度より先に、相手が強打できる高さか。低い球を叩くと負けやすく、低い球を置いて前に出ると勝ちやすい。この因果が1試合で学習されれば生きている。

3. **走ることは報酬にしない。着いて構えたことを報酬にする**  
   報酬は移動距離ではなく、相手が強打しにくい球のあと、2人が止まって横並びでラインに着いた状態。トランジションでの強打は一番損。

4. **既定のゲームはダブルスである**  
   シングルスから作るとテニスと同じ「動いて打つ」に寄る。固有性は真ん中の球、横並び、片方が出たらもう片方も出る。最初のプロトタイプは2対2（片方または両方AIでも可）。

5. **ソフトな球は「つなぎ」ではなく、本体の操作である**  
   テニスゲームはディンク相当を決め球までの待ち時間にしがち。最初に磨く打感は強打より、低い球を意図した場所に置く感触。

### テニス模倣で最初に捨てるもの

- 完璧なタイミングのウィナーが最高の快感
- シングルスの左右に走らせることが本体
- ゲージを溜めて必殺
- ラリーを長く見せるためにキッチンの制約をゆるめる
- サーブからすぐ打ち合いになる（2バウンド・ルールを形だけ残す）

### 最初の試作で検証すること

1. リターン側が先に前へ出る利点が、素人でも一試合で分かるか
2. ドロップして着くことが、ドライブして走るより得だと学習されるか
3. 両方キッチンのあと、先に叩いた側が自滅する感覚が面白いか（ストレスだけではないか）
4. ペアが割れると、真ん中を突かれて「取れていない」と分かるか

1と2が失敗ならフェーズ仮説自体を要修正。3が失敗ならソフトゲームの操作がまだ気持ちよくないか、待つことが罰に見えている。4が失敗ならダブルスが装飾。

### ミス率についての二番目の判断

実プレイでは点の半分前後が最初の数球で終わる。最初はこう置く：

- 学習用の点は、3フェーズが見えるまで生きやすい
- 上手い人同士では、実プレイに近づき、途中で終わる点が増える

先に「フェーズが見える快感」を作り、そのあと短さ（本物のミス）を足す。最初から本物のミス率にすると、固有の体験に届く前にテニス未満の打ち損じゲームになる。

一文に圧縮する：

**ピックルボールのゲームが成立するのは、プレイヤーが「決めた」より先に「キッチンを取った／取られた／両方取った」を言えるときである。**

## 8. 視点：俯瞰より TPS / FPS か

「俯瞰よりFPSの方がピックルボールらしい」と一気に置くより、**テニスの俯瞰が最適化している情報と、ピックルボールが必要とする情報が違う**、と置く方が正確。

テニスの俯瞰は、広いコートの左右と奥行きを見せるためのカメラ。ピックルボールらしさの本体は **高さ、キッチンラインまでの距離、止まっているか走っているか、ペアが横並びか**。この4つが光学的に読めるなら、カメラは俯瞰である必要はない。

テニスと同じ俯瞰でルールだけピックルボールにすると、次が潰れる：

- ボールが「攻撃してよい高さ」かどうかが見にくい
- トランジションを走っている恐怖が、画面上ただの移動に見える
- キッチンが地面の矩形になり、領土に見えない
- 両方ネット前の密な距離感が、小さいテニスに見える

### TPSが強い理由

最初に検証すべきはFPSより、**肩越しのTPS**。自分のパドルと体勢が見え、ボールの高さがネットと相手の胴体を基準に読め、前に走りながら球が足元に来る怖さが残る。着いて構えた瞬間に画面が安定する。これが「走る ≠ キッチンを取る」を説明なしで伝える。

- 取るまで: 奥のキッチンラインが到達目標に見える。ドロップは相手の足元へ沈める行為になる
- 片方だけ: セットか走っているかが、顔の高さで分かる
- 両方: ネットを挟んだ至近距離。ディンクは目の前の高さ勝負になる

テニスでTPSが主流にならない理由は、コートが広すぎて空きコースが見えないこと。ピックルボールはコートが小さく、ネット前の距離は格闘に近い。

### FPSが強い範囲、弱い範囲

FPSは **フェーズ3（両方キッチン）** では強い。実プレイそのものが一人称。浮き球、足元、ポーチ。キッチンを「角度を持ったライン」として持つ感覚も俯瞰より出る。

ただし最初からFPSにすると、別の核が死にやすい：

- ペアの横並びが見えない
- 相手2人の位置関係、真ん中の空きが見えない
- サーブ〜3球目でコート全体のフェーズが読めない
- 速いドライブが画面に張り付き、高さの読みより反射神経ゲームになる

FPSは「ピックルボールらしい」のではなく、**ネット前の決闘らしい**。フェーズ1とダブルスの地図をFPSだけで見せるのは、テニス俯瞰の逆の偏り。フラット画面のFPSは周辺視野が狭い。VRなら別だが、通常は厨房前だけの一人称に留める方が安全。

### 置くべきカメラ仮説

**ピックルボールの視点は、テニスのようにコート全体を常時見せる必要はない。代わりに、ボールの高さと「自分がセットか」が常時見えなければならない。その結果、カメラは低く、近く、フェーズで距離が変わる。**

検証用に分解：

1. 肩越しTPSの方が、俯瞰より「低い球を叩いてはいけない」を早く学習する
2. キッチンに着いて止まったとき、カメラが沈んで安定すると、取る快感になる
3. 走っているあいだカメラが揺れる／視野が狭まると、トランジションの弱さが伝わる
4. ダブルスの横並びは、TPS本体だけでは足りず、パートナーの位置を画面内か最小の地図で補助する必要がある
5. 完全FPSはディンク戦では熱いが、3球目の判断精度を落とす

実務的な始め方：最初から視点を一つに決めない。プロトタイプは **フェーズ連動のTPS** から入る。

- サーブ／リターン: 少し引いて、相手2人とキッチンラインが見える
- 自分が前に出る: 距離を詰め、高さを強調
- 両方キッチン: さらに低く、ネットと相手のパドルが画面の主語になる
- FPSは、この最後の距離だけ切替オプションとして試す

テニスの俯瞰は「地図のゲーム」。ピックルボールをTPS/FPSに寄せる意味は、それを「高さと領土のゲーム」に変えること。らしさの本体は一人称であること自体ではなく、**俯瞰だと消える高さ・足元・着弾のセット感を、視点が主役にすること**。そこがテストに耐えたら、TPSは本線、FPSはネット前の拡張。

## 現行スライスとの関係

いまの `gd-pickleball` は overhead 2D で、クリックがソフト、ダブルクリックがハード、移動は自動、CPUは返球のみ。フェーズは実装上 `SERVE_AIM` / `IN_FLIGHT` / `POINT_END` であり、試合理解上の3フェーズ（取る／片方だけ／両方）はまだプレイヤーに見せていない。

このメモの仮説を次のスライスに落とすなら、優先度は高い順に：

1. プレイヤーが「今キッチンを取れているか」を言えるフィードバック
2. 高さ（叩いてよいか）が、速さより先に読めること
3. 走っている途中の強打が損で、着いてからのソフトが得であること
4. 視点を変えるなら、俯瞰のまま情報を足すより、フェーズ連動のTPSを小さく試す
